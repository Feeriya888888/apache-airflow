# Shop Analytics — ELT на Apache Airflow + ClickHouse

проект: аналитическое хранилище событий интернет-магазина, где
оркестрацией занимается **Apache Airflow**

Бизнес-вопросы, на которые отвечает пайплайн:
- сколько пользователей приходило каждый день (DAU);
- как выглядит воронка `просмотр -> корзина -> покупка`;
- как возвращаются когорты пользователей по месяцам (retention);
- какие товары и каналы привлечения приносят выручку.

## Архитектура

```
extract.py            load.py              SQL внутри ClickHouse
(Python, CSV)   ->   (HTTP, чанками)  ->   raw  --"как есть", String + loaded_at
                                            stg  --типизация, валидация, дедуп (ReplacingMergeTree + FINAL)
                                            mart --витрины (AggregatingMergeTree, VIEW)
```

Python не трансформирует данные — он только извлекает и загружает (EL, буквы E и L).
Вся логика преобразования — декларативный SQL в `sql/`, оркестрация — Airflow DAG.

## Инженерные решения 

- **Слои raw/stg/mart.** raw хранит данные «как есть» — источник всегда можно перечитать;
  stg наводит типы и дедуплицирует; mart — готовые витрины. Это язык, на котором
  думают data-инженеры, и он 1-в-1 переносится на dbt.
- **Идемпотентность.** Генератор детерминированный (фиксированный сид): повторный
  запуск DAG кладёт в raw те же строки — raw накапливает «дубликаты», но stg
  отсекает их через `ReplacingMergeTree(loaded_at)` + чтение с `FINAL`.
  Можно триггерить DAG хоть десять раз подряд — витрины не поедут.
- **Агрегатные витрины.** DAU и выручка считаются заранее в `AggregatingMergeTree`
  через `uniqState`/`sumState` — чтение через `uniqMerge`/`sumMerge` сканирует
  на порядки меньше строк, чем пересчёт по stg.
- **Типизация без потерь.** В stg строки из raw превращаются в `UUID`, `Decimal`,
  `DateTime` через безопасные функции (`toDecimal64OrZero`,
  `parseDateTimeBestEffortOrNull`) — грязная строка не роняет пайплайн, а
  становится `0`/`NULL` и видна в DQ.
- **DQ-проверки как задача DAG.** Пайплайн сам падает, если данные пустые или
  в `stg` остались дубли после `FINAL` — а не молча отдаёт кривые витрины.
- **Load чанками.** Загрузчик шлёт CSV порциями по 200 тыс. строк — память
  не растёт вместе с объёмом данных.
- **Партиционирование и TTL** — см. комментарии в `01_raw.sql` (TTL 24 месяца
  на события) — здесь сырой слой тоже можно нарезать по месяцам.
